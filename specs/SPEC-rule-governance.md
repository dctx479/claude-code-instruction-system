# 规则治理与执行流程精简

日期：2026-11-21；范围：本仓库规则入口、全局安装源、意图路由、规则审计、QA/复盘流程。

## 目标与边界

- 项目约定以 AGENTS.md 为单一来源；CLAUDE.md 引用它，入口各不超过 200 行。
- 全局安装使用独立模板（不超过 60 行），不再复制本仓库工作方式到其他项目。
- 移出入口的细节按需查阅；不删除 Agent/Skill 功能，不批量改写历史记忆。
- 规则审计默认只读，不执行从规则提取的命令；语义不确定的情况交人工确认。
- 第一阶段只做沙箱安装与验证；第二阶段在用户要求继续推进后，按已验证的计划同步相关全局组件。
- 全局激活先 dry-run、备份后写入，不触及凭据、权限和无关配置；不提交、推送或创建 PR。

## 实现

1. 分离 AGENTS.md、CLAUDE.md、config/claude-global.md；Hook 维护约束放路径限定规则。
2. scripts/audit-rules.py 提供清单、规模、导入、路径和可静态核对命令检查；接入 /check 和 CI。
3. Hook 正确解析 JSON，隔离引用/代码内容；长粘贴无法可靠识别时保守返回默认角色。
4. 路由结果直接进入本轮 stdout 上下文；按 session_id 保存状态，全局快照仅供旧 HUD 展示。
5. 按风险选择验收深度；分数不能掩盖失败的验收项，命令必须来自当前项目。
6. /rule-audit 只给证据与 diff；/evolve 和 reflection 要求重复事故证据及更硬保障的评估。

## 验收

- 自动审计入口规模与引用；错误夹具能触发非零退出码，不修改被审计文件。
- 测试真实运行仓库 Hook，覆盖现有角色、引号、多行、粘贴、手动覆盖、坏输入、会话隔离。
- 沙箱安装 core 两次幂等；仅改变托管的旧全局规则，有自定义内容时保留并报告。
- 安装 core 不再部署项目 AGENTS.md，不改用户 settings 的其他键。
- 交付实际运行的命令、结果、未验证项和后续工作；不能以静态检查冒充真实 Claude 会话验证。

## 第二阶段验收

- 实际同步后，托管文件与源一致，原全局入口可从备份恢复；settings 的非托管键保持不变。
- 验证已安装 Hook 的 stdin/stdout；真实 CLI 诊断禁用模型工具和外部通知，失败时保留实际原因。
- 对记忆中的旧同步方向、旧入口预算作局部废弃标记，保留案例原文；修正索引，不批量猜测置信度。
- 精简 neat 的全库遍读要求，使其只同步当前任务影响的文档、规则和记忆。

## 最终收口验收（用户要求一次性完成）

- 验证环境隔离安装 PyYAML；全量 Skill 可移植 schema 检查接入 CI，修复缺头文件，保存自定义元数据和原正文。
- Ralph 全局无归属、跨会话、坏输入和写失败均有行为测试；真实受限 CLI 完成两轮 Stop 接续，不使用生产目录或发送通知。
- 本次真实请求作为路由回归样本；收集本项目聚合使用记录，不导出用户 prompt，不用缺失观测推断低频或停用。
- 两份记忆库做全量结构盘点，历史案例不冒充当前规则；外部三套工作流以固定 commit 比较，选择替换现有环节而不是叠加体系。
- Windows 与 Linux 执行完整 CI 检查。远端 CI 只有实际提交/推送后才可能触发；不擅自发布当前分叉或覆盖远端历史。
