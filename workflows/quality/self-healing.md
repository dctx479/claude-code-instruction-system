# 自我修复质量循环

当前门禁统一见 `docs/QA-SYSTEM.md`。本页只说明 qa-reviewer 与 qa-fixer 的协作，
不另建评分表或把应用示例的性能、覆盖率目标套给所有项目。

## 输入

- 当前需求、已有 Spec 或简短验收清单。
- 本次 diff、任务风险、实际测试输出和未验证项。
- 用户授权范围；自动修复权限不因本流程被扩大。

LOW 任务可以直接在回复中交证据，不强制新建 Spec 或 QA-REPORT.md。
MEDIUM/HIGH 的设计和检查深度按 AGENTS.md 选择；缺陷 P0/P1/P2 与任务风险分开。

## 有界循环

1. qa-reviewer 对照需求和 diff 核对每个必需验收项：
   - PASS：有实际证据且全部通过，无未解决阻塞缺陷。
   - FAIL：验收失败或存在未解决 P0/P1。
   - INCOMPLETE：缺少必需证据、工具或执行条件。
2. PASS 时交付结果；QA 结论本身不授权合并、推送或发布。
3. 存在 P0/P1、缺少权限或无法补充的证据时，说明阻塞及影响，不继续盲修。
4. 有授权范围内可自动修复的 P2 时，qa-fixer 只改对应目标，再运行原失败检查及相关回归。
5. 最多自动修复三轮；每轮都重新检查验收项。仍未通过时明确 FAIL/INCOMPLETE 与剩余原因。

不能用高分抵消必需项失败，也不能把“检查命令已运行”当成“命令成功”。
没有配置的检查说明不适用；没跑过的必需检查不能标通过。

## 验证与回滚

- 命令来自当前项目的 manifest、CI 或已验证入口；太一见 `commands/dev/check.md`。
- 安装、Hook 或状态变更在临时目录验证正常/失败分支，避免真实全局状态被测试污染。
- 修改前记录用户已有 diff。检查失败时保留证据，只撤销能明确归属本次任务的修改。
- 禁止 git checkout .、批量删 import、自动改权限或用静默 fallback 把错误变成成功。
- 性能与覆盖目标来自需求；示例数字不是默认门禁。

## 输出

简单任务给目的、差异与证据即可；复杂任务报告包含：

| 验收项 | 实际检查与运行目录 | 退出码/证据 | 结果 |
|--------|--------------------|-------------|------|
| 具体需求 | 实际运行的命令或检查 | 实际输出 | PASS/FAIL/未验证/N/A |

同时列出风险、缺陷严重度、修复范围、重验结果和未验证项。
角色定义：`agents/qa-reviewer.md`、`agents/qa-fixer.md`。
完整 Spec 流程仅在任务需要或显式选择时调用 `.claude/skills/spec-first/SKILL.md`。
