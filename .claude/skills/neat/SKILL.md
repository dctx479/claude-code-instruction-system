# 任务收尾整理（Neat）

把本次任务已经确认的事实同步到受影响的文档、规则与记忆中。
不因“收尾”默认遍读全仓库，也不为了每层都有修改而制造内容。

## 输入与范围

- 输入：当前任务目标、已确认事实、git diff；用户可以限定目录。
- 先检查工作区，列出本次实际变更的文件、调用者和引用者。
- 只读这些文件及查证所需的邻近内容；仅在用户要求全库审计时扩大范围。
- 历史记忆先搜索标题/关键词，再读相关条目；重号用日期和完整标题区分。

## 整理流程

1. 为每个新事实列影响：给人看的说明、给 Agent 的当前约定、供后续检索的经验。
   没有影响的层标“不需要更新”，不强制追加规则或经验。
2. 对相关文件实际阅读并查证：
   - 命令、路径、安装方向是否仍与代码一致；
   - 是否有重复约定、过期引用或本轮造成的矛盾；
   - 全局安装副本和项目源是否职责混淆。
3. 先修实际执行说明，再修规则，最后按需更新记忆。
   优先合并已有内容；历史案例仍有价值时只标明被替代的建议，保留证据。
4. 新增/强化规则按 /evolve 的证据门槛；仅整理当前任务已确认的事实无需虚构第二次事故。
5. 运行相关检查，区分通过、未验证、不适用。太一规则检查用：
   `python scripts/audit-rules.py --strict`。
   其他项目用其真实 manifest/CI，不直接套太一命令。

## 同步与边界

- 太一仓库的 AGENTS.md/CLAUDE.md 是项目入口，全局入口来自 config/claude-global.md。
- 自动导入仍会占上下文；不能靠 @ 导入长文来冒充预算下降。
- 预算与安全要求遵循当前项目指令；不沿用历史 40K 字符目标。
- 不批量删除、不臆测置信度、不按年龄自动删除记忆；保留用户已有修改。
- 不改业务代码；发现实现缺陷时说明证据，回到对应开发任务处理。
- 涉及真实全局同步或跨项目修改时先检查授权；授权已存在则继续，不重复索要确认。
- 不顺带改凭据、个人权限、生产配置，不自动提交、推送或创建 PR。
- 复盘的经验提炼由 reflection 处理；Neat 不强制新增经验或 Skill。

## 交付与完成

给出：影响范围、逐文件改动及原因、实际检查结果、未验证项和跨项目影响。
能确认的失效引用已修复；不能确认的保留并列为待查，不能宣称全库无问题。
没有必要修改时，给出检查证据即可，不为展示活动制造 diff。
