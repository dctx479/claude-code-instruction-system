# Spec Research Skill

> 灵感来源: AI PPT Agent 的需求调研方法
> 
> 核心理念: **先调研再动手**，像顾问一样提问，而不是凭空臆测

## 功能概述

在编写技术规格或实现功能前，先进行结构化的需求调研，确保真正理解用户需求。

---

## 调研方法论

### 金字塔原理

1. **结论先行**: 先明确最终目标
2. **以上统下**: 上层需求统领下层细节
3. **归类分组**: 相关需求归为一组
4. **逻辑递进**: 按优先级排序

### 调研流程

```
1. 功能目标调研
   ↓
2. 资料搜集（最佳实践）
   ↓
3. 技术约束明确
   ↓
4. 验收标准确认
   ↓
5. 生成调研报告
```

---

## 调研问卷模板

### 第一部分：功能目标

**核心问题**:
1. **核心功能是什么？** 
   - 用一句话描述这个功能
   - 它解决什么具体问题？

2. **目标用户是谁？**
   - 内部开发者？
   - 外部用户？
   - 其他系统？

3. **使用场景？**
   - 在什么情况下使用？
   - 频率如何（高频/低频）？
   - 典型用例是什么？

4. **成功标准？**
   - 如何定义"功能完成"？
   - 质量标准是什么？

### 第二部分：技术约束

**核心问题**:
1. **技术栈限制？**
   - 必须使用的语言/框架？
   - 禁止使用的技术？
   - 现有系统依赖？

2. **性能要求？**
   - 响应时间要求？
   - 并发量要求？
   - 数据量级？

3. **兼容性要求？**
   - 浏览器兼容性？
   - 设备兼容性？
   - 向后兼容性？

4. **安全要求？**
   - 认证授权级别？
   - 数据加密要求？
   - 合规要求？

### 第三部分：资源约束

**核心问题**:
1. **时间约束？**
   - 预期完成时间？
   - 有无硬性 deadline？
   - 分阶段交付？

2. **人力约束？**
   - 有多少开发者？
   - 技术能力如何？
   - 是否需要培训？

3. **预算约束？**
   - 基础设施成本？
   - 第三方服务成本？
   - 维护成本？

### 第四部分：验收标准

**核心问题**:
1. **功能验收？**
   - 如何测试功能完整性？
   - 覆盖哪些场景？
   - 边界条件是什么？

2. **质量验收？**
   - 代码质量标准？
   - 测试覆盖率要求？
   - 文档完整性要求？

3. **交付验收？**
   - 交付物清单？
   - 部署要求？
   - 交接要求？

## 资料搜集策略

### 搜集维度

1. **最佳实践**
   - 行业标准做法
   - 知名项目案例
   - 技术文档

2. **常见陷阱**
   - 已知问题
   - 性能瓶颈
   - 安全隐患

3. **技术选型**
   - 主流方案对比
   - 优缺点分析
   - 适用场景

4. **实现参考**
   - 开源项目
   - 代码示例
   - 教程文章

### 搜集工具

**推荐工具**:
1. **Grok** - 最强的搜索和信息总结能力
2. **web_search** - 内置搜索工具
3. **GitHub Search** - 代码和项目搜索
4. **Stack Overflow** - 问题和解决方案

**搜集模板**:
```bash
# 搜索最佳实践
web_search "[技术] best practices 2025"

# 搜索常见问题
web_search "[技术] common pitfalls"

# 搜索实现案例
web_search "[功能] implementation examples"

# 搜索性能优化
web_search "[技术] performance optimization"
```

## 使用流程

### 步骤 1: 触发调研

```bash
用户: 我需要实现用户认证功能
Agent: 收到，让我先进行需求调研...
```

### 步骤 2: 结构化提问

```bash
Agent: 我需要明确几个关键问题：

## 功能目标
1. 认证方式？
   A. 用户名密码
   B. OAuth 第三方登录
   C. 手机验证码
   D. 生物识别

2. 目标用户？
   A. 内部员工（企业级）
   B. 外部用户（消费级）
   C. API 调用者（开发者）

3. 安全等级？
   A. 普通（个人项目）
   B. 中等（小企业）
   C. 高（金融/医疗）

请告诉我您的选择...
```

### 步骤 3: 资料搜集

```bash
Agent: 明白了，让我搜集一些相关的最佳实践...

[搜索中...]

找到以下参考资料：
1. OAuth 2.0 最佳实践 (IETF RFC)
2. JWT 安全使用指南 (OWASP)
3. 常见认证漏洞及防护 (CVE 数据库)

正在分析...
```

### 步骤 4: 生成调研报告

```bash
Agent: 调研完成！这是我整理的需求调研报告：

[完整报告]

请您确认：
1. 功能目标是否准确？
2. 技术选型是否合适？
3. 验收标准是否明确？

确认后，我将编写详细的技术规格文档。
```

## 注意事项

### 1. 不要凭空臆测

❌ **错误做法**:
```
用户: 实现用户认证
Agent: 好的，我假设你需要 JWT + OAuth...
```

✅ **正确做法**:
```
用户: 实现用户认证
Agent: 我需要先确认几个问题...
```

### 2. 资料搜集必须真实

❌ **错误做法**:
```
Agent: 根据我的了解，最佳实践是...（凭记忆）
```

✅ **正确做法**:
```
Agent: 让我搜索最新的最佳实践...（实时搜索）
```

### 3. 结论必须有依据

❌ **错误做法**:
```
推荐方案: JWT
理由: 这个好
```

✅ **正确做法**:
```
推荐方案: JWT
理由: 
- 无状态，易于扩展（来源: RFC 7519）
- 广泛支持（GitHub, Google 等都在用）
- 性能优于 Session（来源: Auth0 benchmark）
```

## 最佳实践

### 1. 分层提问

```
第一层: 功能是什么？（What）
第二层: 为什么要做？（Why）
第三层: 给谁用的？（Who）
第四层: 怎么验证？（How to verify）
```

### 2. 记录假设

```markdown
## 未明确的假设

假设 1: 用户量 < 10万
假设 2: 只需要支持 Web 端
假设 3: 不需要 SSO

请用户确认或修正
```

### 3. 提供选项而非答案

```
❌ 我们应该用 PostgreSQL
✅ 数据库选型：
   - PostgreSQL: 强大的关系型功能
   - MySQL: 更广泛的生态
   - MongoDB: 灵活的文档存储
   
   您的数据结构更适合...
```
