# 规则演进与废弃

从原 CLAUDE.md 提取的按需参考。执行入口为 `commands/general/evolve.md`，项目约定见 `AGENTS.md`。
补规则前须有两次独立事故证据，并优先评估测试、lint、hook 或权限；以下根因动作仅表示候选方向，不是自动写入授权。

## 八、进化指令

### 废弃规则管理（Deprecation Protocol）

过时规则**标记废弃而非直接删除**，保留 60 天后方可移除。

**废弃标记格式**：

```markdown
> [!NOTE] DEPRECATED 2026-06-10  
> 已废弃，替代方案：[新规则位置或描述]

~~原有规则内容（保留可读但加删除线）~~
```

**适用场景**：
- `deprecate`（标记）：曾经正确但现在过时、有历史参考价值
- `delete`（直接删除）：错误记录、重复条目、无价值噪声

**废弃生命周期**：标记日 → 60 天保留期 → 季度审计时清除

> 详见: `memory/best-practices.md` BP-026（规则提炼）、BP-037（事故驱动增长）

### 规则增长策略（事故驱动）

**只根据事故继续加规则**。不是因为"看起来不够完整"就继续加，而是因为某类错误反复出现（≥2次），所以专门补一条下一次能执行的约定。

CLAUDE.md 是保障栈最轻的一层（L0 软提醒），不能替代 lint(L1)、测试(L2)、hooks(L3)、CI/Review(L4)。规则放对层级比多写规则更重要。

**根因六分类（R1-R6）** — 每次任务偏差必须归因后再决定是否改规范：

| 根因 | 含义 | 动作 |
|------|------|------|
| **R1** 规范缺失 | 该情况没有对应约定 | 补充 Skill / CLAUDE.md 规则 |
| **R2** 规范冗余 | 规则太多互相矛盾或无法遵守 | 精简 / 合并条目 |
| **R3** 规范过时 | 工具/环境已变但规则未更新 | 同步更新，旧版加废弃标记 |
| **R4** Review 漏洞 | 检查项不完整导致问题流出 | 补 review 清单项 |
| **R5** 代码 bug | 代码逻辑错误，非规范问题 | 修代码，不动规范 |
| **R6** 外部因素 | 网络/API/第三方变更 | 记录，不一定改规范 |

**铁律**：R5 / R6 不触发规范进化；R1-R4 才是补规则的合法依据。

> 详见: `memory/best-practices.md` BP-036（防御纵深）、BP-037（事故驱动规则增长）、BP-051（R1-R6 根因闭环）

复杂任务按需调用 reflection；写经验前查重，保留案例与验证方法。
完整复盘与 diff 提案流程统一维护在 /evolve，不在此复制另一套步骤。
