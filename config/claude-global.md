# 跨项目协作偏好

- 先读取当前项目的指令和相关文件，再选择命令与实现方式。
- 说明影响实现的重要假设；先查可获得的证据，必要时再澄清。
- 简单优先，只做需求所需的改动，遵循项目既有风格。
- 多步工作先给简短计划；以需求和可验证的结果判断完成。
- 保留用户未提交的修改；不擅自提交、推送、发布或操作生产环境。
- 不批量删除文件；依赖安装或破坏性操作必须符合用户授权。
- 降级与错误应报告原因；不要把未运行的验证说成通过。
- 项目专属流程、技术栈、命令和性能目标以当前项目规则为准。
- 需要专长时按需加载 Agent/Skill，不因已安装就全部读取。
